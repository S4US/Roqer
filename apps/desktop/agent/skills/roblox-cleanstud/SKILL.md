# CLEANSTUD (Stud UI Clean Roblox)

A complete, measured design system extracted from a shipped Roblox simulator (17 ScreenGuis, ~7,700 instances) plus a
**tested component kit** that rebuilds it from scratch. Your job when this skill triggers: produce UI that is
indistinguishable from the reference screenshots, by building through the kit instead of hand-placing frames.

`references/screenshots.md` describes each reference capture. Capture 20 shows the original shop next to the same
window generated by this kit — that is the quality bar.

This skill replaces `roblox-ui-design`'s theme, layout and polish references for the screen. Roqer's validation rule
still applies (step 5).

## What makes the style (keep these, they are the identity)
1. **3D stud buttons**: dark outline (ImageButton background) → darker *Biseau* lip at the bottom (the thickness) →
   *Face* CanvasGroup with a bright vertical gradient, two diagonal hard-edged glass streaks (one light, one dark),
   a tiled stud texture fading in toward the bottom-right, a double 1 px inner bevel and a 2 px bottom glow. No corners.
2. **Heavy outlined text**: only Montserrat Heavy (windows) and GothamSSm Heavy (HUD) (+ Montserrat Bold for
   descriptions). Every label has a Contextual stroke 2–4 px in a *dark tint of its background* (never plain black),
   and important labels are **extruded**: a dark copy 2 px below the white text.
3. **Dark glass windows**: colored stud header (or the pink shop header texture) with a 96 px icon overflowing the
   top-left corner rotated −10°, 50 px title, red chunky X; body = black at 50 % transparency with a thin white
   second frame; the world stays visible behind, blurred (18) with FOV +8.
4. **Sticker icons** from the bundled CheckUIIcons library, "… 1st Outline" variants, tilted −8°/−10°/−12°, overflowing.
5. **Dark item slots** with a spinning sunburst behind the icon, 3 px black border + light inner line, lime selection.
6. **Strict color semantics**: green = in-game money / confirm, purple = Robux / skip, red = shop / locked / destroy,
   blue = primary navigation, yellow/orange = premium / claim-all / restock, gray = done. Rarities Common → Cosmic.
7. **Pixel geometry + one UIScale**: everything in offset px for a 1050×620 screen, each root scaled by a `WindowScale`
   UIScale = clamp(min(vx/1050, vy/620), 0.52, 1.18). This keeps 1 px bevels and 4 px lips crisp on every device.
8. **Springy motion**: press 0.92 in 0.05 s, Back-Out release, bouncy open (0.86 → 1, 0.32 s), fast close (0.16 s),
   sunbursts always spinning, badges pulsing, a sound on every interaction.

## Workflow

1. **Identify the archetype** (layouts-and-archetypes.md §3): product-list shop, collection grid + tabs, reward calendar,
   upgrade/prestige, season pass, premium offers, reward banner, HUD element. Read the matching capture in
   `references/screenshots.md` and the matching example.
2. **Install the kit** in the place (once). `game.ReplicatedStorage` needs ModuleScripts `StudUI`, `StudMotion` and
   `CheckUIIcons` that hold the kit exactly:
   - Create the missing ones empty in one `build_instances {path: "game.ReplicatedStorage", operations: [{op: "create", className: "ModuleScript", name: "StudUI"}, …]}`.
   - Write each with `set_script_source {instancePath: "game.ReplicatedStorage.StudUI", template: "roblox-cleanstud/templates/install/StudUI.lua"}`, and the same for `StudMotion` and `CheckUIIcons`. Roqer copies the file; a module that already holds it exactly is left alone. Never retype the kit.
   - A module of that name that holds anything else (an older kit, or the user's own edits) is not overwritten unasked: tell the user, and replace it only once they agree, with the revision from `get_script_source {line_range: "1"}`.
3. **Build in Edit mode** into `StarterGui`, through a builder like the examples. Never rebuild UI on every spawn.
   - Write the builder as a ModuleScript in `ServerStorage.CleanStudBuilders` (a Folder; create it the first time) with
     `set_script_source`. Its first line is `-- theme: cleanstud`; the rest is `return function(UI, Icons, parent) … end`
     as in the examples. Pass `Icons.Get` exact paths from the catalog files.
   - Run it with this `execute_luau`, changing only `BUILDER`. It clones each module before requiring it, so an edited
     builder is never served from `require`'s cache; it replaces what the builder made last time, keeps the scripts
     added to those ScreenGuis since (a menu's controller), and marks each ScreenGui it makes with a
     `CleanStudBuilder` attribute:
     ```lua
     local RS, SS, StarterGui = game:GetService("ReplicatedStorage"), game:GetService("ServerStorage"), game:GetService("StarterGui")
     local BUILDER = "NestShop" -- the builder's name in ServerStorage.CleanStudBuilders

     local function fresh(module)
     	local copy = module:Clone()
     	local ok, result = pcall(require, copy)
     	copy:Destroy()
     	if not ok then error(result, 0) end
     	return result
     end

     local kept = {}
     for _, gui in StarterGui:GetChildren() do
     	if gui:GetAttribute("CleanStudBuilder") == BUILDER then
     		for _, child in gui:GetChildren() do
     			if child:IsA("LuaSourceContainer") then
     				child.Parent = nil
     				table.insert(kept, { gui = gui.Name, script = child })
     			end
     		end
     		gui:Destroy()
     	end
     end
     local before = {}
     for _, gui in StarterGui:GetChildren() do before[gui] = true end
     fresh(SS.CleanStudBuilders[BUILDER])(fresh(RS.StudUI), fresh(RS.CheckUIIcons), StarterGui)
     local made, dropped = {}, {}
     for _, gui in StarterGui:GetChildren() do
     	if not before[gui] then
     		gui:SetAttribute("CleanStudBuilder", BUILDER)
     		table.insert(made, gui.Name)
     		for _, entry in kept do
     			if entry.gui == gui.Name then entry.script.Parent = gui end
     		end
     	end
     end
     for _, entry in kept do
     	if entry.script.Parent == nil then table.insert(dropped, entry.gui .. "." .. entry.script.Name) end
     end
     return { made = made, dropped = dropped }
     ```
     A script listed in `dropped` belonged to a ScreenGui the builder no longer makes; tell the user.
4. **Wire behaviour** with a LocalScript `MenuController` inside each menu ScreenGui (not the HUD's): create it with
   `build_instances`, then write it with `set_script_source {template: "roblox-cleanstud/templates/examples/06_MenuController.client.lua"}`
   when the standard wiring is enough, or with source of your own based on it. It gives `Motion.Window`,
   `Motion.BindButton`, `Motion.SpinSunbursts` and the purchase feedback (`Motion.Float`, `Motion.Shake`). A HUD button
   opens a menu by firing that menu's `Basculer` event.
5. **Verify**. Load `references/core/validation.md` from `roblox-ui-design`: Roqer does not verify a run that changed
   interface until an `inspect_ui {mode: 'audit'}` after the last change comes back clean. In a solo playtest, a menu
   starts closed: open it from the client with `eval_client_runtime`
   (`game.Players.LocalPlayer.PlayerGui.<Menu>.Basculer:Fire(true)`; without a controller, set its `Fenetre.Visible = true`).
   Audit `game.Players.<player>.PlayerGui.<Menu>`, fix what it names, then `capture_screenshot` and compare with the
   capture's description and `references/checklist.md`. For motion, also check blur 18, FOV +8 and the other GUIs
   hidden, then restored on close; read `get_runtime_logs`. Stop the playtest, and never leave test instances or
   changed properties in the user's place.

To **edit** a CLEANSTUD screen (a ScreenGui with a `CleanStudBuilder` attribute), change its builder in
`ServerStorage.CleanStudBuilders` with `set_script_source`, reading its revision first, and run step 3 again. Keep
the screen's layout and unrelated geometry.

## Rules of thumb (with the reason)
- **Offsets, not scale** — the bevels are 1–4 px; scale sizes round them away. One WindowScale per root handles devices.
- **Build through the kit** — a hand-made flat button misses 9 of the 10 layers that make it read as 3D.
- **Tint every outline** — `#26020A` on red, `#022826` on blue, `#1A2402` on green… Pure black makes it look generic.
- **Extrude labels** — the 2 px dark copy under white text is what gives the "toy" depth; `UI.ShadowText` does it.
- **Never opaque windows** — black @0.5 + blur keeps the game world present; it's a simulator, the world is the reward.
- **Let things overflow and tilt** — header icons, tile icons, badges, "OP"/"VALUE!" stickers. Perfect alignment looks corporate.
- **Same component, different size for hierarchy** — the primary action is the bigger blue button, not a new style.
- **Keep the French instance names** (`Fenetre`, `Entete`, `Corps`, `Biseau`, `Face`, `Fond`, `Texte`, `Ombre`, `Icone`…):
  runtime scripts (recolor, tabs, disabled state, menu controllers) find parts by these names.
- **Motion is part of the style** — no menu should appear without the bounce, no button without hover/press, no sunburst static.
- Use exact icon paths from `references/icons/<category>.md`, "1st Outline" variants by default.

## Extending the style
New color theme for a button = 4 colors: a 3–5 stop bright `fond` gradient (lighter top), a 2-stop `biseau` ~45 % darker,
a near-black `bord` of the same hue, a very dark `texte` tint. New rarity = text gradient (light → saturated) + tab theme +
optional panel image. New window = pick the closest archetype and reuse its proportions; header color from `UI.HeaderThemes`
or a new 3-stop vertical gradient in the same luminance range. Keep corner radii ≤ 6 and stroke thicknesses in the table.
